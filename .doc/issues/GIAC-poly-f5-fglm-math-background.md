# GIAC-poly F5 FGLM —— 数学背景

**配套 plan:** [GIAC-poly-f5-fglm-over-coefficient-field](GIAC-poly-f5-fglm-over-coefficient-field.md)
**用途:** 用 plain language 解释该 plan 的数学动机与结构，不涉及 Rust 实现细节。

---

## 一句话

让 giac-rs 在解一类四次方程（Galois 群 = A₄）时，**少绕一次弯路**，把分裂域维数从 24 降到 12 —— 方法是给「在扩域里开平方」这个探测步骤，补一块目前缺的数学工具：**在 ℚ(α) 系数域上跑 Gröbner 基 + FGLM**。

---

## 1. 背景：四次方程的根法

解 `x⁴ + px + q = 0` 这种四次方程，标准做法（Ferrari / resolvent cubic）里会冒出一个 **判别式的平方根 `√Δ`**。这个 `√Δ` 在不在某个已构造的扩域里，直接决定下一步要不要再「盲扩」一次：

- 如果 `√Δ` **已经在**当前域里 → 不用再扩 → 维数省一半。
- 如果 **不在** → 只好再 adjoin 一个二次扩张 → 维数翻倍。

giac-rs 现在有个函数 `try_sqrt_in_field`，专门做「探测 `√u` 在不在当前扩域里」。它已经有一套结构性探测（S0–S6），但对 A₄ 这种情形会 **miss** —— 不是因为数学上不在，而是因为探测手段不够强。

---

## 2. 现在的状况 vs 目标

**A₄ 例子**：`x⁴ + 8x + 12`，Galois 群是 A₄，分裂域维数应该是 **12**。
- 现状：探测 miss → 盲扩 → 维数变成 **24**（多一倍，答案还对，就是浪费）。
- 期望：探测命中 → 维数 **12**。

**S₄ 例子**：`t⁴ + t + 1`，Galois 群是 S₄，分裂域维数本来就该是 **24**。
- 这个必须 miss（数学上 `√Δ` 确实需要再扩），盲扩是对的，不能动。

所以目标很明确：**让 A₄ 命中、S₄ 仍然 miss**，两条路分开。

---

## 3. 数学结构（为什么是 12）

A₄ 四次方程的分裂域长这样：

```
ℚ  ⊂  ℚ(α)       α 是 4 次方程的一个根        [ℚ(α):ℚ] = 4
 ⊂  ℚ(α, β)     β 是在 ℚ(α) 上再 adjoin 3 次   [ℚ(α,β):ℚ(α)] = 3
                                              总维数 = 4 × 3 = 12
```

关键事实：

- 对 **A₄**，`√Δ ∈ ℚ(α,β)` —— 12 维塔域**就是**完整分裂域。
- 对 **S₄**，`ℚ(α,β)` 才 12 维，但 S₄ 分裂域要 24 维 —— `√Δ ∉ ℚ(α,β)`。`ℚ(α,β)` 只是 S₄ 的某个固定子域，不是分裂域。

所以探测的就是：**在 12 维塔域 `ℚ(α,β)` 里，`√Δ` 在不在？**

---

## 4. 怎么探测：把「开平方」变成「解方程组」

在塔域顶层，`β` 是 3 次的，所以任何元素能写成

```
x = x₀ + x₁·β + x₂·β²     其中 x₀, x₁, x₂ ∈ ℚ(α)
```

我们要找 `x` 使得 `x² = Δ`。把上式代入，按 `β` 的幂展开对齐系数，得到

> **3 个二次方程、3 个未知数 `x₀, x₁, x₂`，系数在 `ℚ(α)` 里**

这是个 0-dim（有限解）的小方程组，解只有 `±√Δ` 两个。解多元多项式方程组的标准武器是 **Gröbner 基**。

---

## 5. 为什么不直接干，要分步

工程上有几个拦路石，plan 的优先级就是逐个搬开：

### P0 — Gröbner 代码现在只认 ℚ，不认 ℚ(α)
`giac-groebner` 现在写死了 `Poly<Ratio<BigInt>>`（即 ℚ 系数）。要解系数在 ℚ(α) 里的方程组，得先把它**泛型化**到 `C: FieldCoeff`。底层抽象已经准备好，只是 groebner 这一层没接上。

### P1 — 还得换一种变量序（grevlex）
Gröbner 基用的变量序很关键。直接用 **lex 序**（字典序）跑这种 `x² = u` 形状的方程组，中间多项式度数会爆炸（实测 120s 跑不完）。换成 **grevlex 序**（先比总次数）跑 0-dim 系统就很快。所以得加 grevlex 比较 + grevlex 版 Buchberger。

### P2 — FGLM：把 grevlex 基翻成 lex 基
grevlex 跑得快，但形状不「三角形」，读不出 `x₀, x₁, x₂` 的值。lex 基才是三角形（`x₂ = …, x₁ = …, x₀ = …`），能直接回代。**FGLM** 就是这个翻译器：用线性代数（乘法矩阵 + Krylov 求极小多项式）把 grevlex 基转成 lex 基。本问题解只有 2 个，转换很轻。

### P3 — 接线：把上面的工具装进探测函数
在 `try_sqrt_in_field` 现有 6 个探测阶段后加一个 **S7**：当看到「12 维塔域、顶层 3 次」这种结构，就用 P0–P2 的工具解那 3 个二次方程，命中就返回 `√Δ`，miss 就退回原来的盲扩兜底。S₄ 因为顶层结构不同，根本不会进 S7，自动保持 miss。

### P4 — 回归测试
确认 A₄ 降到 12、S₄ 还是 24，全套测试绿。

---

## 6. 目标验收（DoD）

| 场景 | 维数 |
|---|---|
| `x⁴ + 8x + 12` (A₄) | ≤ **12**（从 24 降下来，探测命中） |
| `t⁴ + t + 1` (S₄) | ≤ **24**（不变，探测正确 miss） |

两个方程的四根都用 `verify_root` 验证正确，全套测试不回归。

---

## 7. 为什么这事值得做

不是修 bug —— 现在答案本来就对。是**补一条算法链**：giac 的「扩域求根」管线原本就指望 `try_sqrt_in_field` 能识别 `√Δ ∈ 当前域` 的情形，rust 移植在这一格上探测能力不足，导致 A₄ 这类方程无谓多扩一次。补上后，A₄ 维数对齐 giac 的 12，S₄ 保持 24，**数学语义和 giac 一致，且不再因探测缺失而浪费维数**。这是「先达 golden 等价」原则下补全算法缺口，不是叠特例。

---

## 8. Upstream 对标状态（重要）

本 plan **不是 golden 等价任务**，是 rust 侧超越上游的扩展。实测 giac-2.0.0 二进制（`./build/bin/giac`）：

| 上游命令 | 结果 |
|---|---|
| `solve(x^4+8*x+12, x)` | `[]` |
| `solve(t^4+t+1, t)` | `[]` |
| `solve(x^4+1, x)` | `[]`（连 cyclotomic 四次都放弃） |
| `solve(x^4-2, x)` | `list[-2^(1/4), 2^(1/4)]`（只给实根，复根丢） |
| `factor(x^4+8*x+12)` | `x^4+8*x+12`（ℚ 上不可约） |
| `discriminant(x^4+8*x+12, x)` | `331776` = 576²（平方 → Gal ⊆ A₄） |
| `discriminant(t^4+t+1, t)` | `229`（非平方 → Gal = S₄） |
| `proot(...)` | 两方程各 4 个数值复根 |

结论：

- **上游 exact `solve` 对不可约四次根本就返回 `[]`**，不只 A₄ 这条。所以 **没有 upstream exact-solve golden 可对标** —— 上游这条链路本身就没打通。
- 全仓 grep `x^4+8*x+12` 在 `.doc/`、`tests/`、`scripts/` 无任何 golden/check 命中；rust 的 `quartic_a4_galois_dim_le_12` 是 `#[ignore]` 测试，DoD 是「4 根 `verify_root` + `dim ≤ 12`」，**不是** golden 等价。
- **上游能给的、已打通的是旁证**：`factor` 确认不可约 → adjoin degree-4 α 有依据；`discriminant` = 576²/229 → Galois 群判定（A₄/S₄）有依据；`proot` 给 4 数值复根 → `verify_root` 期望根数=4 有交叉印证。**数学结论由上游判别式 + Galois 理论共同验证，不依赖上游 exact solve。**
- 项目规则正好覆盖：「绑定数学语义 + 测试规格，不绑定 giac C++ 行级实现」「giac 有 bug/错答 → Rust 用正确行为」「无测试覆盖 → 自订语义，补测试」。上游 `solve` 连 `x^4+1` 都返回 `[]` 属能力缺失，rust 侧建塔域求 exact 根是规则允许的「用正确行为」。

**一句话：** 上游 exact-solve 链路本身没打通（返回 `[]`），本 plan 的 dim-12 目标是**数学正确性目标**（Galois 理论 + `verify_root` 验证），不是上游行为复刻。
